# Spec Delta

## Purpose

Пускать в приложение только тех, кто подтвердил свою почту ссылкой из письма, чтобы каждый работал под своей почтой со своими данными. Паролей нет: первый вход по ссылке и есть регистрация.

## ADDED Requirements

### Requirement: Без входа приложение закрыто

Все страницы приложения MUST быть доступны только после входа. Невошедший пользователь на любой странице MUST видеть страницу входа. Без входа доступны только страница входа, страница «Ссылка устарела», адреса, по которым работает вход, и проверка работы сервера `/health`. Действия сервера (сохранение, удаление и т. п.) без входа MUST NOT выполняться.

#### Scenario: Открыл приложение без входа

- **WHEN** невошедший пользователь открывает главную
- **THEN** он видит страницу входа: поле «Почта» и кнопку «Получить ссылку»

#### Scenario: Прямая ссылка без входа

- **WHEN** невошедший пользователь открывает адрес страницы контакта или страницы «Группы»
- **THEN** он видит страницу входа, данных контакта или групп на странице нет

#### Scenario: Запрос к серверу без входа

- **WHEN** запрос на изменение данных (например, сохранение контакта) приходит к серверу без входа
- **THEN** сервер ничего не меняет и не отдаёт данных

#### Scenario: Проверка сервера без входа

- **WHEN** выкатка открывает `/health` без входа
- **THEN** ответ как раньше: `"status":"ok"` и версия

#### Scenario: Вошедший открывает страницу входа

- **WHEN** вошедший пользователь открывает адрес страницы входа
- **THEN** приложение открывает главную

### Requirement: Запрос ссылки для входа

На странице входа пользователь вводит почту и нажимает «Получить ссылку». После этого страница MUST показать «Ссылка для входа отправлена на ‹почта›», а на почту MUST уйти письмо со ссылкой. Ответ одинаковый для нового и для уже известного адреса: по нему нельзя понять, есть ли такой пользователь. Исключение - сработал лимит писем.

#### Scenario: Ввёл почту

- **WHEN** пользователь вводит `anna@example.com` и нажимает «Получить ссылку»
- **THEN** на странице написано «Ссылка для входа отправлена на anna@example.com»
- **AND** на `anna@example.com` приходит письмо со ссылкой для входа

#### Scenario: Новый и известный адрес неотличимы

- **WHEN** ссылку запрашивают для почты, под которой ещё никто не входил, и для почты существующего пользователя
- **THEN** в обоих случаях один и тот же текст «Ссылка для входа отправлена на ‹почта›»

#### Scenario: Пока запрос отправляется

- **WHEN** пользователь нажал «Получить ссылку», а ответ сервера ещё не пришёл
- **THEN** кнопка неактивна, повторное нажатие не отправляет второе письмо

### Requirement: Правила адреса почты

Пробелы в начале и в конце почты MUST убираться, большие и маленькие буквы MUST NOT различаться: `Anna@Example.com` и `anna@example.com` - один пользователь. Неверный адрес MUST давать ошибку под полем «Проверьте адрес почты», письмо при этом не уходит. Сервер MUST проверять почту по тем же правилам, даже если запрос пришёл не из формы.

#### Scenario: Пробелы и большие буквы

- **WHEN** пользователь вводит «  Anna@Example.COM  » и входит по ссылке из письма
- **THEN** он попадает к тем же данным, что и при входе под `anna@example.com`
- **AND** в шапке написано `anna@example.com`

#### Scenario: Неверный адрес

- **WHEN** пользователь вводит «anna@» или оставляет поле пустым и нажимает «Получить ссылку»
- **THEN** под полем написано «Проверьте адрес почты», письмо не уходит
- **AND** введённый текст остаётся в поле

#### Scenario: Неверный адрес в обход формы

- **WHEN** запрос на отправку ссылки с адресом «anna@» приходит к серверу не из формы
- **THEN** сервер отвечает ошибкой, письмо не уходит

### Requirement: Лимит писем

На один адрес почты MUST уходить не больше 3 писем со ссылкой за 10 минут. Четвёртый запрос в эти 10 минут MUST показать «Слишком часто, попробуйте через несколько минут», письмо не уходит. Лимит считается по почте после приведения к одному виду (без пробелов, маленькими буквами).

#### Scenario: Четвёртое письмо за 10 минут

- **WHEN** пользователь трижды за 10 минут запросил ссылку на `anna@example.com` и запрашивает в четвёртый раз
- **THEN** на странице написано «Слишком часто, попробуйте через несколько минут»
- **AND** четвёртое письмо не приходит

#### Scenario: Через 10 минут снова можно

- **WHEN** с первого из трёх писем прошло больше 10 минут
- **THEN** новый запрос отправляет письмо и показывает «Ссылка для входа отправлена на ‹почта›»

#### Scenario: Другой регистр не обходит лимит

- **WHEN** три письма ушли на `anna@example.com`, и запрос приходит на `ANNA@example.com`
- **THEN** показывается «Слишком часто, попробуйте через несколько минут», письмо не уходит

#### Scenario: Лимит одного адреса не мешает другому

- **WHEN** лимит для `anna@example.com` исчерпан, и запрашивают ссылку на `boris@example.com`
- **THEN** письмо на `boris@example.com` уходит

### Requirement: Письмо со ссылкой

Письмо MUST приходить от «Личная CRM» с адреса `noreply@mail.crm.lyna.tech`, с темой «Вход в Личную CRM». В письме MUST быть кнопка «Войти» со ссылкой для входа, текст о том, что ссылка работает 15 минут, и текст «Если вы не запрашивали вход - просто проигнорируйте письмо».

#### Scenario: Содержимое письма

- **WHEN** пользователь запросил ссылку
- **THEN** в письме отправитель «Личная CRM» `<noreply@mail.crm.lyna.tech>`, тема «Вход в Личную CRM»
- **AND** в письме кнопка «Войти», фраза о 15 минутах и «Если вы не запрашивали вход - просто проигнорируйте письмо»

### Requirement: Вход по ссылке

Открытие ссылки из письма MUST впускать пользователя в приложение и открывать главную с его контактами. Первый вход с новой почты MUST создавать пользователя без отдельной формы регистрации; имя не спрашивается.

#### Scenario: Вход по ссылке

- **WHEN** пользователь открывает ссылку из свежего письма
- **THEN** открывается главная, в шапке его почта, видны его контакты

#### Scenario: Первый вход - регистрация

- **WHEN** под почтой `vera@example.com` ещё никто не входил, и пользователь входит по ссылке на эту почту
- **THEN** пользователь создан, открыта главная с пустым списком и текстом «Контактов пока нет. Добавьте первый.»

### Requirement: Ссылка одноразовая и живёт 15 минут

Ссылка для входа MUST срабатывать один раз и только 15 минут с отправки. Запрос новой ссылки на ту же почту MUST отменять все прежние неиспользованные ссылки. Старая, уже использованная, отменённая или неверная ссылка MUST открывать страницу «Ссылка устарела, запросите новую» с кнопкой, ведущей на страницу входа; входа при этом не происходит.

#### Scenario: Повторное открытие ссылки

- **WHEN** пользователь вошёл по ссылке, вышел и открывает ту же ссылку снова
- **THEN** он видит «Ссылка устарела, запросите новую» и кнопку перехода на страницу входа, в приложение не попадает

#### Scenario: Ссылка старше 15 минут

- **WHEN** пользователь открывает ссылку через 16 минут после отправки письма
- **THEN** он видит «Ссылка устарела, запросите новую», в приложение не попадает

#### Scenario: Запросил новую ссылку

- **WHEN** пользователь запросил ссылку, потом запросил ещё одну и открывает первую
- **THEN** он видит «Ссылка устарела, запросите новую»
- **AND** вторая ссылка впускает его в приложение

#### Scenario: Испорченная ссылка

- **WHEN** пользователь открывает ссылку входа с изменённым или выдуманным кодом
- **THEN** он видит «Ссылка устарела, запросите новую»

#### Scenario: Кнопка на страницу входа

- **WHEN** на странице «Ссылка устарела» пользователь нажимает кнопку
- **THEN** открывается страница входа с полем почты

### Requirement: Срок входа

Вход MUST держаться 30 дней с последнего захода в приложение на этом устройстве: каждый заход продлевает срок. После 30 дней без заходов приложение MUST снова показать страницу входа. Пользователь MAY быть вошедшим с нескольких устройств одновременно, вход на одном не выкидывает с другого.

#### Scenario: Заходит регулярно

- **WHEN** пользователь заходит в приложение раз в неделю
- **THEN** вход не пропадает, страницу входа он не видит

#### Scenario: Не заходил больше 30 дней

- **WHEN** с последнего захода на этом устройстве прошло больше 30 дней
- **THEN** приложение показывает страницу входа

#### Scenario: Два устройства

- **WHEN** пользователь вошёл на ноутбуке, а потом вошёл на телефоне
- **THEN** на ноутбуке он по-прежнему в приложении

### Requirement: Шапка и выход

На всех страницах приложения после входа в шапке MUST быть почта пользователя и кнопка «Выйти». «Выйти» MUST завершать вход только на этом устройстве и открывать страницу входа. На страницах входа и «Ссылка устарела» почты и «Выйти» нет.

#### Scenario: Почта в шапке

- **WHEN** пользователь `anna@example.com` вошёл и открыл любую страницу приложения
- **THEN** в шапке написано `anna@example.com` и есть кнопка «Выйти»

#### Scenario: Выход

- **WHEN** пользователь нажимает «Выйти»
- **THEN** открывается страница входа
- **AND** при открытии главной снова показывается страница входа

#### Scenario: Выход только на этом устройстве

- **WHEN** пользователь вошёл на ноутбуке и на телефоне, и нажал «Выйти» на телефоне
- **THEN** на ноутбуке он по-прежнему в приложении

### Requirement: Куда уходят письма

Куда уходят письма MUST определяться настройками, а не кодом: одна и та же сборка приложения работает на компьютере разработчика, в автотестах и на сервере. На компьютере разработчика и в автотестах (в том числе на GitHub) письма MUST попадать в почтовую заглушку, а не к настоящим адресатам; войти можно под любым адресом. На сервере письма MUST уходить настоящим адресатам через почтовый сервис.

#### Scenario: Письмо на компьютере разработчика

- **WHEN** приложение запущено локально, и пользователь запросил ссылку на `test-a@example.com`
- **THEN** письмо видно на странице почтовой заглушки, по ссылке из него можно войти
- **AND** настоящее письмо никуда не уходит

#### Scenario: Письмо в автотестах

- **WHEN** автотест запрашивает ссылку для входа
- **THEN** автотест забирает ссылку из почтовой заглушки, настоящих писем нет

#### Scenario: Письмо на сервере

- **WHEN** пользователь на сервере запросил ссылку на свою настоящую почту
- **THEN** письмо приходит в его почтовый ящик

### Requirement: Автотест входа двух пользователей

MUST быть автотест в браузере, проверяющий вход двух пользователей A и B через почтовую заглушку и то, что B не видит данных A. Автотест главного сценария из `specs/01-продуктовая-идея.md` MUST оставаться отдельным: перед сценарием он входит под пользователем.

#### Scenario: Критерий успеха из спеки

- **WHEN** A вошёл по ссылке и добавил контакт, затем B вошёл по ссылке
- **THEN** у B контакта A нет ни в списке, ни в поиске
- **AND** по прямой ссылке на контакт A у B открывается «Контакт не найден»

#### Scenario: Не видят данных друг друга

- **WHEN** A и B вошли по ссылкам, и каждый добавил свой контакт и свою группу
- **THEN** у B нет контакта и группы A, у A нет контакта и группы B: ни в списке, ни в поиске, ни на странице «Группы», ни в фильтре
- **AND** прямая ссылка на чужой контакт у обоих открывает «Контакт не найден»
