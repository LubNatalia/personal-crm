# Design

## Context

Зачем — см. proposal.md, что должно работать — см. specs/keep-in-touch/spec.md, как выглядит — см. «Макеты» ниже.

Что есть сейчас:

- Таблица `contacts` (`src/db/schema.ts`): заметки — одно текстовое поле `notes`; есть `created_at` и `updated_at`, но `updated_at` меняется при правке любого поля, поэтому день последнего общения из него не узнать.
- Форма контакта одна для нового и существующего контакта (`src/components/contact-form.tsx`), значения разбирает и проверяет `parseContactForm` (`src/lib/contact-form.ts`), сохраняют server actions в `src/app/actions.ts`. После сохранения вызывается `revalidatePath` для главной и карточки. Форма пересоздаётся только по своему ключу `instance` (сброс при уходе со страницы), а не при обновлении данных страницы.
- Next.js 16 с `cacheComponents`: посещённые страницы остаются в DOM скрытыми (React Activity) — у формы уже есть обходы для этого. Главная динамическая (читает `searchParams`), карточка читает базу на каждый запрос.
- Контейнер приложения на сервере работает в UTC; заголовок карточки («Добавлен … · изменён …») сейчас форматируется в часовом поясе сервера.
- Автотестов и тестовой библиотеки в проекте нет; прошлую фичу проверяли Playwright-скриптом из временной папки.

## Goals / Non-Goals

**Goals:**

- Одно место, где считается «день, когда пора связаться» и «на сколько просрочено», — и для блока, и для карточки.
- Фильтрация и сортировка блока — в базе, без загрузки всех контактов в приложение.
- Миграция только добавляет столбцы: без переписывания таблицы и без изменения существующих данных.

**Non-Goals:**

- История общений и список заметок с датами.
- Отметка общения задним числом (галочка ставит только «сегодня»).
- Настройка часового пояса в интерфейсе.
- Автотесты в репозитории: тестовая библиотека — это новая зависимость, её обсуждаем отдельно.

## Decisions

### 1. Три новых столбца в `contacts`

- `contact_frequency` — тип-перечисление Postgres `contact_frequency` со значениями `week`, `month`, `quarter`, `year`; `NULL` — «Не задано».
- `last_contacted_at timestamptz` — когда последний раз отметили общение: новой строкой в `notes` или галочкой «Связались»; `NULL` — неизвестно.
- `frequency_set_at timestamptz` — когда частоту сменили с «Не задано» на значение; `NULL`, пока частота не задана.

Начало отсчёта = `coalesce(last_contacted_at, frequency_set_at)` — ровно правило из спеки: известно общение — от него, нет — от дня, когда задали частоту.

Почему заметка и галочка пишут в один столбец: на экране одна подпись «Последнее общение», различать, чем его отметили, не нужно.

Почему два времени, а не одно: одно поле смешало бы «когда общались» и «когда начали следить». Тогда нельзя показать «Последнее общение: не отмечено» и нельзя корректно отработать «убрали частоту и задали снова».

Почему перечисление, а не `text`: база сама не пустит неизвестное значение, а Drizzle даёт готовый тип в TypeScript. Добавить вариант позже — одна миграция `ALTER TYPE … ADD VALUE`.

Отдельную таблицу общений не делаем: хранить в ней нечего, кроме той же даты.

### 2. Новую заметку определяем при сохранении, в транзакции

Правило «появилась новая строка, прежние не тронуты» — чистая функция `hasNewNoteLines(previous, next)` в `src/lib/`:

- текст делится на строки, у каждой обрезаются пробелы по краям, пустые строки отбрасываются;
- прежние строки должны встречаться в новом тексте в том же порядке (как подпоследовательность), а строк в новом тексте должно быть больше;
- прежний текст пустой — любая непустая строка новая.

Правка строки, дописывание в её конец, удаление строк и «поправил и дописал за одно сохранение» не проходят: прежней строки в новом тексте нет. Новая строка внизу, вверху или в середине проходит.

`updateContact` выполняется в транзакции:

1. `SELECT notes, contact_frequency … FOR UPDATE` (в Drizzle — `.for("update")`) читает прежние значения и блокирует строку до конца транзакции, чтобы сохранение из второй вкладки не вклинилось между чтением и записью.
2. `UPDATE` с новыми значениями полей и:
   - `last_contacted_at = now()`, только если `hasNewNoteLines(прежние, новые)`; иначе столбец не трогаем;
   - `frequency_set_at`: частота «Не задано» → `NULL`; была «Не задано», стала значение → `now()`; иначе не трогаем.

Сравниваются значения после `parseContactForm` (обрезаны пробелы по краям, пустая строка → `NULL`). Время — из базы (`now()`), как и остальные даты.

При создании контакта: `last_contacted_at = now()`, если заметки заполнены; `frequency_set_at = now()`, если частота выбрана.

Почему в коде, а не одним SQL-выражением: сравнение «строка за строкой по порядку» в SQL получается громоздким и плохо читается, а функцию на TypeScript легко проверить на примерах.

Почему строки, а не «текст стал длиннее»: исправление опечатки, добавившее букву, тоже удлиняет текст.

### 3. Галочка «Связались»: отметить и снять

Два server action в `src/app/actions.ts`, запросы — в `src/db/contacts.ts`:

- `markContacted(id)` — в транзакции читает `last_contacted_at` и `contact_frequency` с `FOR UPDATE`. Частота не задана — ничего не делает. Иначе `last_contacted_at = now()`. Возвращает `{ previous, markedAt }`: прежнее значение и время отметки.
- `unmarkContacted(id, markedAt, previous)` — `UPDATE contacts SET last_contacted_at = $previous WHERE id = $id AND last_contacted_at = $markedAt`. Условие не даёт отмене затереть общение, отмеченное позже (например, новой заметкой из другой вкладки): тогда ничего не меняется, и галочка остаётся. `previous` должен быть не позже `markedAt`, иначе запрос отклоняется.

Данные для отмены (`previous`, `markedAt`) держит браузер, в базе их нет. Поэтому снять галочку можно, только пока страница не обновлена, — так же, как в блоке, где после обновления отмеченных уже нет. Лишний столбец не нужен.

Отметка не меняет `updated_at`: «изменён …» в заголовке карточки — про правку полей. Форма карточки не пересоздаётся (её ключ не зависит от данных), поэтому несохранённые правки в полях остаются.

`markContacted` и `unmarkContacted` вызывают `revalidatePath` только для карточки контакта, главную не трогают: строки блока остаются такими, какими пришли, а отмеченные показывает сам блок (решение 7). Свежие данные главная получит при обновлении страницы или новом переходе на неё.

Почему только «сегодня»: в требованиях — «Связались сегодня»; отметка задним числом — отдельное решение.

### 4. Сроки считаем в SQL, по московскому времени

Одно SQL-выражение в `src/db/contacts.ts`, общее для блока и карточки:

- `start_day = (coalesce(last_contacted_at, frequency_set_at) AT TIME ZONE 'Europe/Moscow')::date`
- `due_day = (start_day + <интервал>)::date`, где интервал по частоте: `7 days`, `1 month`, `3 months`, `1 year`
- `today = (now() AT TIME ZONE 'Europe/Moscow')::date`
- `overdue_days = today - due_day` (целое; `0` — «пора сегодня», больше нуля — просрочено)
- `contacted_today = (last_contacted_at AT TIME ZONE 'Europe/Moscow')::date = today` — для галочки в карточке

Postgres сам прижимает число к концу месяца (`31 января + 1 month = 28 февраля`, `29.02.2028 + 1 year = 28.02.2029`) — это ровно правило из спеки.

Блок: `WHERE contact_frequency IS NOT NULL AND overdue_days >= 0 ORDER BY overdue_days DESC, name COLLATE "ru-x-icu", id` — тот же порядок по имени, что и в общем списке.

Карточка: те же поля для одного контакта (`due_day`, `overdue_days`, день последнего общения, `contacted_today`, `today`).

Даты из базы передаём строками `YYYY-MM-DD` (`to_char`), чтобы при разборе в JavaScript день не съехал из-за часового пояса. `markedAt` и `previous` для отмены — точные метки времени строкой ISO.

Почему SQL, а не TypeScript: фильтр и сортировка сразу в базе; «сегодня» берётся из одних часов — часов базы; не нужен `new Date()` при отрисовке, с которым у Cache Components свои ограничения; не нужна библиотека для арифметики месяцев.

Часовой пояс — одна константа `APP_TIME_ZONE = "Europe/Moscow"`, она же в SQL и в форматировании дат. Без неё на сервере (UTC) заметка в 01:00 по Москве попала бы на вчерашний день.

Заодно заголовок карточки («Добавлен … · изменён …») форматируем в том же поясе — иначе на одной странице время в заголовке (UTC) и «Последнее общение» (Москва) могут разойтись на день. Локально ничего не изменится, на сервере время в заголовке станет московским.

### 5. Показ дат и чисел

- Дата: `Intl.DateTimeFormat("ru-RU", { day, month: "long" })` → «2 октября»; если год не совпадает с годом `today`, добавляется год без «г.»: «10 сентября 2025».
- Дни: `Intl.PluralRules("ru-RU")` → «1 день», «3 дня», «5 дней», «21 день».
- Последнее общение: дата известна — «Последнее общение: 2 октября»; неизвестна — «Последнее общение: не отмечено».
- Отмеченная строка блока — «Связались сегодня».

Эти функции — в одном модуле в `src/lib/`, их используют и блок, и карточка.

### 6. Карточка: поле частоты, строки о сроке, галочка, подсказка

- В форму добавляется поле `contactFrequency`: значения `""` (не задано), `week`, `month`, `quarter`, `year`. `parseContactForm` пропускает только их; иначе — ошибка у поля «Выберите вариант из списка» (через интерфейс не случится, защита от подделанного запроса).
- Элемент — нативный `<select>` в стиле полей формы: компонент `native-select` из shadcn/ui, если он есть в реестре для текущего стиля, иначе небольшой свой компонент в `src/components/ui/` на тех же токенах, что `Input`. Новых библиотек нет.
  Почему нативный, а не `Select` на Base UI: на телефоне открывается системный список, значение само попадает в `FormData`, а `defaultValue` и сброс формы работают так же, как у остальных полей, — это важно из-за React Activity.
- Место: в сетке полей рядом с «Почта» — там сейчас пустая ячейка; под полем — строки о сроке, под ними галочка.
- Строки о сроке и признак `contacted_today` считает страница карточки на сервере и передаёт в форму готовыми. После сохранения или отметки `revalidatePath` обновляет страницу, и строки показывают новые значения без перезагрузки. На странице «Новый контакт» строк и галочки нет.
- Галочка — клиентский компонент: `<button type="button" role="checkbox" aria-checked>` с подписью «Связались сегодня» (кнопка не отправляет форму). Кружок 24 px, зона нажатия не меньше 44 px. Состояния:
  - не отмечено — пустой кружок с рамкой цвета акцента;
  - отмечено на этой странице — закрашенный кружок с галочкой, можно снять (у компонента есть `previous` и `markedAt`);
  - `contacted_today`, но данных для отмены нет (отмечено заметкой или до обновления страницы) — закрашенный кружок, `aria-disabled`, снять нельзя.
- Подсказка под «Заметками» — «Новая строка — новое общение: срок отсчитывается заново», текст цвета `ink-muted`, связан с полем через `aria-describedby`. Показывается, когда у сохранённого контакта задана частота.

### 7. Блок на главной

- Серверный компонент получает данные; главная запрашивает их параллельно со списком и счётчиком, только когда нет поиска. Выборка возвращает всех, у кого пора. Пустой результат — блок не выводится.
- Список строк — клиентский компонент: он получает строки один раз и хранит, какие отмечены (`id` → `previous`, `markedAt`). Отмеченная строка остаётся на месте, N в заголовке = строк минус отмеченные. После обновления страницы сервер этих контактов уже не вернёт.
- Вид — как в макете (`mockups/home-desktop.png`, `home-desktop-marked.png`, `home-phone.png`): белая карточка, заголовок «Пора связаться (N)» внутри; в строке слева кружок-галочка (вместо аватара), затем имя, частота, пометка срока и «Последнее общение: …». На компьютере колонки строк выровнены, на телефоне строка складывается в столбик. Цвета и отступы — только токены из `tokens.css`.
- Вся строка открывает карточку, а кружок — нет. Чтобы не вкладывать кнопку в ссылку, ссылка — только имя, а её невидимая область `::after` растянута на всю строку (`position: absolute; inset: 0`). Кружок лежит поверх (`position: relative; z-index`) и ловит нажатие сам. Кружок — `<button role="checkbox" aria-checked aria-label="Связались: ‹имя›">`, зона нажатия не меньше 44 px.
- Отмеченная строка: кружок закрашен, галочка белая; остальное содержимое строки — с прозрачностью (бледное); вместо пометки срока — плашка «Связались сегодня» в цвете акцента.
- Пометка срока — плашка с иконкой часов (`Clock` из `lucide-react`, библиотека уже в проекте): «Просрочено на N дней» — коралловая (`coral-50` / `coral-700`), «Пора сегодня» — в цвете акцента. Галочка — `Check` из той же библиотеки.
- Длина: все строки приходят сразу, первые 5 видны, остальные показывает и прячет кнопка «Показать всех» / «Свернуть» (`aria-expanded`) — без запроса к серверу и без параметра в адресе. Начальное состояние — свёрнуто. Кнопки нет, если строк 5 или меньше. При возврате на главную внутри приложения блок может остаться раскрытым (React Activity хранит состояние) — спека требует свёртывания только после обновления страницы.

### 8. Тестовые данные

`src/db/seed.ts` (только на пустой базе): примерно каждому десятому контакту задаётся частота, `frequency_set_at` и `last_contacted_at` — в последние месяцы, так что часть из них в блоке, часть ещё нет. Фиксированное зерно генератора сохраняется — данные одинаковые при каждом запуске.

### 9. Проверка

- `pnpm lint`, `pnpm build`.
- Миграция на временном Postgres в Docker (не на рабочей базе).
- Сценарии из спеки — Playwright-скриптом из временной папки (в репозиторий не попадает). Нужные даты в прошлом выставляются SQL-запросом во временной базе. Вид сверяется со снимками в `mockups/`.

## Risks / Trade-offs

- [Дописал в ту же строку или поправил и дописал за одно сохранение — общение не засчитано] → так решено правилом; подсказка под «Заметками» напоминает писать с новой строки, а галочка позволяет отметить общение без заметки.
- [Галочку поставили по ошибке и обновили страницу — снять уже нельзя] → так решено: отмена до обновления страницы. Если будет мешать — хранить прежнюю дату в базе отдельным столбцом.
- [После перехода внутри приложения на карточку и обратно главная может получить свежие данные — отмеченный контакт пропадёт раньше обновления страницы] → требования это допускают: они говорят только об обновлении страницы.
- [`previous` для отмены приходит из браузера] → отмена срабатывает, только если `last_contacted_at` всё ещё равно `markedAt`, а `previous` не позже `markedAt`; приложение личное, других пользователей нет.
- [Часовой пояс зашит: Москва] → одна константа; поменять — одна строка. Если вы живёте в другом поясе, скажите до реализации.
- [Много просроченных] → видны первые 5, остальные по кнопке. Все строки приходят с сервера сразу; при сотнях просроченных страница станет тяжелее — тогда остальные можно догружать по кнопке.
- [Заметки, изменённые до выкатки, — без даты] → правило «от дня, когда задали частоту» и подпись «не отмечено».
- [Откат на предыдущий образ после миграции] → старый код новые столбцы не трогает и не ломается; общение, отмеченное на старой версии, не обновит `last_contacted_at` (на старой версии нет ни правила новой строки, ни галочки). Миграция при откате не отменяется (как и раньше).

## Migration Plan

1. `pnpm db:generate` создаёт миграцию: `CREATE TYPE contact_frequency …` и три `ALTER TABLE contacts ADD COLUMN …` без значений по умолчанию. Postgres добавляет такие столбцы мгновенно, таблица не переписывается, у всех строк — `NULL` (то есть «Не задано» и «не отмечено»).
2. Выкатка обычная: merge в main → образ → разовый контейнер с миграциями → новый образ → smoke `/health`.
3. Откат — только вручную, `rollback.sh` (см. Risks).
