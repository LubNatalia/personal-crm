# Spec Delta

## Purpose

Делить данные между пользователями: у каждого контакта и каждой группы есть владелец, и пользователь видит и меняет только своё. Чужие данные недоступны ни в интерфейсе, ни прямым запросом к серверу.

## ADDED Requirements

### Requirement: У контактов и групп есть владелец

Каждый контакт и каждая группа MUST принадлежать ровно одному пользователю - тому, кто их создал. Заметки принадлежат владельцу контакта. Связь «контакт в группе» MUST быть возможна только между контактом и группой одного владельца.

#### Scenario: Новый контакт принадлежит автору

- **WHEN** пользователь A добавляет контакт
- **THEN** контакт виден у A и не виден ни у кого другого

#### Scenario: Новая группа принадлежит автору

- **WHEN** пользователь A создаёт группу «Теннис» на странице «Группы» или из карточки контакта
- **THEN** группа видна у A, у других пользователей её нет

#### Scenario: Чужую группу нельзя привязать к контакту

- **WHEN** запрос на сохранение контакта A приходит к серверу с номером группы пользователя B
- **THEN** контакт сохраняется без этой группы, группа B не меняется

### Requirement: Пользователь видит только своё

Список контактов, счётчик «Всего», поиск, карточка контакта, заметки, страница «Группы» со счётчиками, поле «Группы» в карточке, фильтр по группе и блок «Пора связаться» MUST показывать только данные текущего пользователя.

#### Scenario: Список и поиск

- **WHEN** у A есть контакт «Вера Козлова», и B ищет «Козлова»
- **THEN** у B «Веры Козловой» нет ни в списке, ни в результатах поиска, счётчик её не учитывает

#### Scenario: Блок «Пора связаться»

- **WHEN** у A есть контакт, с которым пора связаться
- **THEN** в блоке «Пора связаться» у B этого контакта нет

#### Scenario: Группы и фильтр

- **WHEN** у A есть группа «Аналитики»
- **THEN** у B её нет ни на странице «Группы», ни в фильтре на главной, ни в поле «Группы» карточки

#### Scenario: Чужая группа в адресе

- **WHEN** B открывает адрес главной с фильтром по номеру группы A
- **THEN** показаны все контакты B, в фильтре выбрано «Все», как для несуществующей группы

#### Scenario: Новый пользователь

- **WHEN** пользователь вошёл впервые
- **THEN** список пуст, текст «Контактов пока нет. Добавьте первый.», блока «Пора связаться» и ряда фильтра нет
- **AND** на странице «Группы» текст «Групп пока нет. Создайте первую — например, «Семья» или «Теннис».»

### Requirement: Чужое не открывается и не меняется

Пользователь MUST NOT открывать, менять, удалять или отмечать «связались» чужой контакт, а также переименовывать или удалять чужую группу - ни через интерфейс, ни прямым запросом к серверу с номером чужой записи. Чужой контакт по прямой ссылке MUST выглядеть как несуществующий: страница «Контакт не найден». Чужая запись при этом остаётся без изменений.

#### Scenario: Чужой контакт по прямой ссылке

- **WHEN** B открывает адрес страницы контакта A
- **THEN** B видит страницу «Контакт не найден», данных контакта на ней нет

#### Scenario: Изменение чужого контакта запросом к серверу

- **WHEN** запрос на сохранение, удаление или отметку «связались» с номером контакта A приходит от B
- **THEN** контакт A не меняется и не удаляется

#### Scenario: Изменение чужой группы запросом к серверу

- **WHEN** запрос на переименование или удаление группы A приходит от B
- **THEN** группа A не меняется и не удаляется

### Requirement: Группы у каждого свои

Набор групп у каждого пользователя MUST быть своим. Одинаковые названия групп у разных пользователей MUST быть разрешены.

#### Scenario: Одинаковые группы у разных людей

- **WHEN** у A есть группа «Друзья», и B создаёт группу «Друзья»
- **THEN** группа создаётся, у каждого своя «Друзья» со своими контактами

### Requirement: Существующие данные становятся данными владельца приложения

При выкатке все контакты, заметки, группы и связи «контакт в группе», которые уже есть в базе, MUST стать данными пользователя с почтой владельца приложения. Ни одна запись MUST NOT потеряться: контактов, групп и связей после выкатки столько же, сколько до, поля и заметки те же. Если такого пользователя ещё нет, он создаётся; войти под этой почтой можно обычной ссылкой из письма.

#### Scenario: Первый вход владельца после выкатки

- **WHEN** владелец приложения входит по ссылке на свою почту после выкатки
- **THEN** он видит все контакты, заметки и группы, которые были до выкатки, «Всего» то же число, что до выкатки

#### Scenario: Другой пользователь после выкатки

- **WHEN** после выкатки входит пользователь с другой почтой
- **THEN** у него пустой список, прежних данных он не видит

#### Scenario: Количество записей

- **WHEN** выкатка завершилась
- **THEN** число контактов, групп и связей «контакт в группе» в базе равно числу до выкатки

### Requirement: Демо-данные у владельца приложения

Демо-данные для проверки MUST создаваться у пользователя с почтой владельца приложения. Если такого пользователя нет, он создаётся.

#### Scenario: Демо-данные

- **WHEN** в пустой базе запускают создание демо-данных, и владелец входит по ссылке
- **THEN** он видит демо-контакты и демо-группы
- **AND** у других пользователей их нет

### Requirement: Откат после выкатки входа

Откат после выкатки этой функции MUST делаться только вместе: база восстанавливается из бэкапа, снятого перед выкаткой, и запускается прошлая версия приложения. Порядок отката MUST быть описан в README.

#### Scenario: Откат

- **WHEN** после выкатки входа владелец решает откатиться
- **THEN** в README описано: восстановить базу из бэкапа перед выкаткой скриптом restore, затем запустить прошлую версию приложения
